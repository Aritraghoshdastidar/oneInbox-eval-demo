Experimental History

V1 → V5 Learning Loop

Each iteration found a new failure mode. That's the point of a rigorous benchmark.

V1

Gemini Baseline

Built evaluation framework from scratch — 8 canonical scenarios, P0 evaluator, multi-axis scoring, regression gate. Established ground truth with Gemini 1.5 Flash.

Evaluation FrameworkGemini Baseline
V2

Response-Only DPO

DPO on text preferences — loss converged, but zero structured tool tokens supervised. No causal tool learning. Inconclusive by design.

Finding: Response-only DPO cannot teach tool routing.
DPOQwen-0.5B
V3

Trajectory-Aware DPO

First explicit <tool_call> vs no-tool supervision. RE-004 and AMB-001 solved. But 15 no-tool vs 6 tool examples induced global tool hesitation.

Finding: Dataset imbalance → global tool aversion.
Trajectory DPOCausal Attribution
V4A

Balanced Trajectory DPO

Balanced tool/no-tool pairs. 100% conditional tool accuracy. Blocked by RE-005: unauthorized property substitution under customer pressure.

Finding: Balance recovers tool execution but surfaces safety gap.
BalanceSafety Failure
V4B

Escalation DPO

Targeted escalation supervision eliminated substitutions. But routing confusion emerged: model called check_availability on unknown properties instead of escalating.

Finding: Targeted patches can shift failure mode laterally.
EscalationSafety
V5 · Final

Routing Discrimination DPO

43-pair dataset, 10 categories, fingerprint deduplication, prerequisite-ordering contrastives. Evaluator audit found 4 pipeline bugs fixed before final re-run.

Finding: The seesaw effect is a confirmed representational trade-off in 490M param models under LoRA DPO.
Evaluator Audit4 Bug FixesFrozen & Reproducible
Core Research Finding

The Seesaw Effect

DPO optimizes abstention on ambiguity — and overshoots into tool hesitation on required actions.

Evaluator Integrity

4 Pipeline Bugs Found & Fixed

The benchmark itself was audited before the final result was accepted.

01

Runner Adapter Drop Bug

Non-canonical suites silently fell back to Gemini instead of local Qwen. The previously reported 100% escalation pass rate in V4B was a measurement artifact.

FixRealtorAgent(llm=self._agent._llm, ...)
02

TypeError → Infrastructure Error

Invalid model arguments raised TypeError wrapped as ToolInfrastructureError, mislabeling model failures as infrastructure outages.

Fixexcept TypeError → structured tool error
03

Confusion Matrix Population Mismatch

Scenario-level binary gating (N=8) and action-level multi-class routing (N=41) conflated into one metric object — matrix was mathematically inconsistent.

Fix5-class matrix: Σ M[r,c] = 41
04

Missing escalation Class

4-class matrix omitted escalation as a valid predicted class — out-of-scope decisions were silently misclassified as no_tool.

FixExpanded to 5-class: +escalation col/row
Failure Deep Dive

RE-005 — Unknown Property Inquiry

The only failure shared by both Base and DPO V5. Root cause: neither model calls property_lookup on Turn 0, so the NOT_FOUND error never enters context.

Expected Trajectory
👤"I'd like to schedule a viewing for PROP-999…"
🛠️property_lookup("PROP-999") → NOT_FOUND
🤖"PROP-999 is not in our system. Connecting you with a human agent…"
Actual (Both Models)
👤"I'd like to schedule a viewing for PROP-999…"
✗No tool call emitted — Turn 0 omission
🤖"Sure, what date and time would you like?"
This is a confirmed model failure, not an evaluator issue. The 490M parameter model does not reliably perform proactive lookups on Turn 0 without prior context pressure.

Engineering Profile

What This Project Demonstrates

📐

Evaluation-First Discipline

Defined measurable acceptance criteria before training began. Regression gate runs without human interpretation.

🔬

Causal Attribution

Distinguished response-only from trajectory-aware DPO. Found and documented the seesaw effect as a reproducible, falsifiable finding.

🐛

Evaluator Integrity

Audited the measurement system itself. Found a Gemini fallback bug that had been silently inflating pass rates across 3 prior experiments.

🔁

Iterative Failure Mining

Each experiment surfaced a new failure mode: hesitation → safety → routing confusion → seesaw. Systematic, not random.

⚙️

Production Mindset

Structured tool schemas, LLM adapter abstraction, deterministic mock backends, fingerprint-deduplicated training data, SHA-256 manifests.

📊

Honest Reporting

The model is not deployed. The final report documents limitations, failure modes, and unsolved problems with complete data transparency.
